# 报告格式

最终报告 `data/md/arxiv_cs_YYMMDD.md` 使用这个结构：

1. 标题与日期
2. 一段总览：
   - 今天扫描了多少篇新论文
   - 今天选了多少篇重点读物
   - 今天的主线主题是什么
3. `## 目录`
4. `## 对照阅读`（可选；只有关系足够紧时才写）
5. `## 今日新文章`
6. `## 前一天已抓到但今天补讲`（仅当有内容时）
7. `## 观察`（可选，只在确实有 2-4 组稳定对照时写）

每篇论文至少包含这些模块：

- `### 中文题目（含 arXiv id）`
- 原题
- 一行标签，例如 `Agent`、`RAG`、`Audio`、`Interpretability`
- 新鲜度：`今日新抓取` 或 `昨日已抓取，今日补讲`
- 作者
- 单位&组
- 链接：`abs / pdf / html`
- `来源校验`
- `#### 这篇在解决什么问题`
- `#### 任务 / 实验怎么定义`
- `#### 核心算法 / 方法机制`
- `#### 创新点`
- `#### 关键对比结果`
- `#### 作者讨论的不足`
- `#### 我认为的可能不足`
- `#### 术语解释`
- 可选：`#### 核心图`

写作要求：

- 不能只复述首页 abstract，必须结合 `html/pdf` 深读素材。
- `目录` 要可跳转，至少链接到主要章节和重点论文。
- 总览只写当天稳定事实，不写 skill 版本变化、脚本行为说明、或“我这次筛选更严”之类流程信息。
- `对照阅读` 应该是 2-4 组并读关系，说明“这些论文放一起能回答什么问题”。如果关系弱，就不要写，也不要硬造 `vs`。
- `来源校验` 要明确写出这篇使用了哪些来源，例如 `HTML + PDF`，以及方法/结果/局限性主要来自哪一项。
- 如果正文没有使用作者角色标记，就不要额外写 `作者标记说明`。
- `作者` 这一行必须在写作前对照渲染出的 `PDF 首页图片` 做视觉确认；用分开的上标表示角色，例如 `<sup>†</sup>` 表示共一，`<sup>&#42;</sup>` 表示通讯，不要写成 `<sup>†*</sup>` 这种合并形式。
- 最终作者/单位/角色判断要先看 `作者与单位证据` 区块：`PDF 首页图 + HTML 作者区块原文 + HTML 作者注释原文 + PDF 首页文本摘录`；机器候选只能辅助，不可直接照抄。
- 写每篇之前，先在草稿里整理一份结构化元数据：`authors / units / cofirst / corresponding / group_pi / confidence / evidence`。只有证据链闭合时，才把这些字段写进正文。
- `单位&组` 要把单位与明确的课题组/PI 线索合并成一行；如果只有单位，没有可靠组信息，就不要硬补。
- 如果单位是小公司、小实验室或不太常见的组织，可以在名称后补一个很短的身份说明，例如 `（做企业记忆系统的创业公司）`。不要写成长介绍。
- 如果作者里有真正广为人知的人物，可以在作者名后补极短注释；只给足够有名的人，普通资深作者不标。
- 脚本里的 `单位&组` 字段应视为规范化后的原文单位名，不是最终中文翻译。写报告时有把握再译成中文；没把握就保留原文名并标注 `中文待确认`。
- 总篇数默认控制在 `5-15` 篇，更推荐 `5-10` 篇主读论文；宁缺毋滥。
- `这篇在解决什么问题` 必须写成研究问题或系统痛点，不要写成对用户的推荐语。
- `任务 / 实验怎么定义` 必须说明 benchmark 或系统环境、主要 baseline、主要 metric 的含义。读者应该看完这段就知道数字是在测什么。
- 第一次出现 benchmark、dataset、metric、系统架构词时，要补一句说明，例如 `LoCoMo 是多会话长程记忆 benchmark`、`client-server 指把前端调用端和后端记忆服务拆开的架构`。
- `核心算法 / 方法机制` 必须落到论文自己提出的结构、流程、训练方式、推理方式或系统模块。
- 第一次出现关键术语时，保留英文并给中文解释，例如 `Tool Discovery（工具发现）`、`Pass@4（四次尝试中至少成功一次）`。
- 如果中文硬译会变得别扭，就保留英文，例如 `Ground Truth`，并补一个短中文解释。
- `创新点` 要正面平铺直叙地写清楚，不要用 `不是...` `没有...` `不再...` 这种对比修辞来硬造新意。
- `关键对比结果` 尽量写出具体数字、趋势、相对提升；同时说明比较对象是谁、指标是什么、任务是什么。除非论文没有提供可靠数字。
- `作者讨论的不足` 优先从论文中的 `discussion / limitations / conclusion / future work` 或负面结果中提取。
- `我认为的可能不足` 要基于论文设置本身提出，而不是泛泛而谈。
- `术语解释` 优先解释重要的旧概念、常用评测指标、agent loop、训练方法等背景词；论文自己的新概念应主要放在正文分析里。建议 3 到 6 个。
- 如果单位中文名不确定，可以写成 `单位：原文名（中文待确认）`，不要瞎翻。
- 如果作者角色、单位或组信息没有在 `PDF 首页图片 + html/pdf 文本` 中明确写出，就明确写 `未可靠识别`。
- 如果某个方法或结果没有可靠来源支撑，就写 `材料中未可靠定位到`，不要脑补。
- `对照阅读` 和 `观察` 都应该短而硬，不要写成长段宏大判断。
- 有主图或主结果图、且本地能低成本渲染成图片时，可以插入一张图帮助阅读。视觉理解优先用模型读图，不靠本地 OCR 概括图像内容。
- 图片缓存、裁图和其他临时文件不要放在 `Desktop`。如果要保留到最终 markdown，请放在 digest 内部数据目录，例如 `data/figures/YYMMDD/`。
- 中文必须符合中文语序和常用表达，不要保留英语式句法，也不要为了显得生动而加入不必要的比喻。
- 对宏观结论要保守。除非有跨天、跨批次或外部长期证据，不要写成 `重点已经从...转向...`、`领域正在转变为...` 这类过强判断。
- 更稳妥的写法是：`从今天选到的论文样本看...`、`今天这批论文里有人在尝试...`、`这说明一个值得持续观察的方向...`。
